# Требования: поиск по истории смет

## Цель
Быстро находить сохранённые сметы по номеру или имени клиента прямо в разделе «История смет».

## Требования
- Над списком истории добавить поле с видимой подписью «Поиск по номеру или клиенту» и подсказкой «Например, СМ-001 или Алия».
- Обновлять список по мере ввода, вставки и удаления текста, без кнопки поиска и без нажатия Enter. Фокус остаётся в поле поиска.
- Искать в сохранённых полях «Номер сметы» и «Для кого». Запись подходит, если весь запрос встречается как часть хотя бы одного из этих полей.
- Не учитывать регистр букв и пробелы в начале и конце запроса. Например, «  аЛиЯ  » находит клиента «Алия». Внутренние пробелы и остальные символы сравниваются буквально; «е» и «ё» различаются.
- Пустой запрос или запрос из одних пробелов показывает всю историю. Удаление текста возвращает полный список без перезагрузки.
- Сохранять прежний порядок записей: новые сверху. Записи с одинаковыми номерами остаются отдельными результатами.
- При наличии истории, но отсутствии совпадений показывать «Ничего не найдено. Измените запрос».
- Если история пуста, показывать существующее сообщение «Вы ещё не сохранили ни одной сметы», независимо от запроса. Ошибку чтения истории не заменять сообщением об отсутствии совпадений.
- Отсутствующие номер и клиент не считаются текстом «Без номера» и «Клиент не указан» для поиска. Такие записи видны при пустом запросе либо при совпадении в другом заполненном поле.
- Кнопка «Открыть» в результатах открывает именно выбранную запись с прежним подтверждением замены текущей сметы. Поиск и отмена открытия не меняют текущую смету, черновик или сохранённые записи.
- При сохранении новой сметы сохранять введённый запрос и обновлять результаты с учётом фильтра. Новая запись видна, только если соответствует запросу; сообщение об успешном сохранении остаётся доступным.
- Запрос не записывать в localStorage. После загрузки страницы поле пустое и показана вся доступная история.
- Поле доступно с клавиатуры, имеет видимый фокус и удобно на телефоне. Поиск не включать в PDF и текст WhatsApp.

## Примеры
Исходная история, от новых записей к старым:
1. «СМ-002», клиент «Алия», 20 000 ₸.
2. «СМ-001», клиент «ТОО Альфа», 15 000 ₸.
3. «СМ-001», клиент «Алия Иванова», 10 000 ₸.
4. Без номера и клиента, 0 ₸.

| Запрос | Результат |
| --- | --- |
| `см-001` | Записи 2 и 3 в прежнем порядке |
| `001` | Записи 2 и 3 |
| `алия` | Записи 1 и 3 |
| `  аЛиЯ  ` | Записи 1 и 3 |
| `альф` | Только запись 2 |
| `СМ-001 Алия` | Нет совпадений: запрос целиком не встречается в одном поле |
| `несуществующий клиент` | «Ничего не найдено. Измените запрос» |
| Пустой текст или пробелы | Все четыре записи |
| `Без номера` | Нет совпадений: служебная подпись не является номером |

При запросе «алия» сохранить новую смету для «Алия»: она появляется первой среди результатов. Сохранить смету для «Борис»: она не появляется в результатах, но доступна после очистки поиска.

## Ограничения
- Только HTML, CSS и обычный JavaScript; работа локально и без интернета, без библиотек и сетевых запросов.
- Поиск не меняет формат хранения истории и не записывает отфильтрованный список вместо полной истории.
- Поиск по сумме, дате, отправителю и услугам, исправление опечаток, транслитерация, регулярные выражения и подсветка совпадений не входят в эту версию.
- Расчёты, скидка, НДС, валюты, сумма прописью, PDF, WhatsApp, каталог, реквизиты, черновик и сохранение/открытие истории сохраняют своё поведение.

## Готово, когда
1. Все примеры дают указанные результаты, включая поиск по части номера и имени, регистр и пробелы по краям.
2. Результаты обновляются при вводе, вставке и удалении текста без Enter; фокус не теряется.
3. Очистка запроса показывает весь список; порядок и отдельные записи с одинаковыми номерами сохраняются.
4. Пустая история, отсутствие совпадений и ошибка чтения истории отображаются как разные состояния.
5. Открытие отфильтрованной записи полностью восстанавливает нужную смету; отмена подтверждения ничего не меняет.
6. Ввод запроса не меняет форму, черновик, реквизиты или содержимое истории; после перезагрузки запрос пустой, история сохранена.
7. Сохранение при активном поиске добавляет запись в полную историю и обновляет результаты по текущему запросу; проверены совпадающая и несовпадающая записи.
8. Пустые поля, длинный запрос и специальные символы (например, `[`, `*`, `<`) не вызывают ошибок, не интерпретируются как регулярные выражения или HTML.
9. На ширине 360 px поле и результаты доступны без горизонтальной прокрутки истории; поиск и открытие работают с клавиатуры, фокус виден.
10. После изменений проверены расчёты, скидка, НДС, четыре валюты, сумма прописью, PDF, WhatsApp, каталог, реквизиты и сохранение/восстановление черновика. Нет NaN, Infinity и неверных денежных сумм.
11. В PDF и тексте WhatsApp остаётся только текущая смета, без поля поиска и результатов истории.

## Статус
Требования подготовлены для согласования. Код изменяется после команды «делай».
